# 买方挂单成交与卖方挂单管理

依据2026-11-18最新确认：不恢复此前三档价格偏离的自动成交、人工审价、大偏离拒绝机制，也不建设复杂的自动撮合引擎；补充产品团队接受指定买单和窗口报价改价触发同价成交两条明确路径。

## Bison Group买方挂单监控及手动成交

Bison Group产品团队可查看买方未成交挂单，包含机构、产品、面值、挂单价格、购买日、退出日和有效期。选择指定订单并确认后，按该买方挂单价接受整笔订单。成交前复核买方账户权限、订单未超时/未撤销、产品开放状态、卖方可用库存和买方可用资金；不允许重复成交。

原先“产品团队不能代替交易双方决定成交”的限制被本次明确授权调整。新建卖方挂单仍使用显式卖方交易权限，不把产品团队角色等同于所有卖方交易能力。产品团队最终使用端和模块可见性仍按既有待确认事项管理，目前按用户指定在Group提供操作。

## 修改窗口报价触发同价成交

用户已经确认：仅买方挂单价等于卖方报价时成交，按该相同价格成交。买价高于或低于卖价都不触发自动成交，不使用价差容忍阈值或“买价不低于卖价”的算法。

报价必须限定同一产品、同一购买日和退出日窗口。Group有权限人员在报价管理中调整窗口报价，系统核验尚有效的买单，逐笔执行同价且满足交易条件的订单；报价更新和成交记录各自留痕，含价格、窗口、版本、操作者和时间。过期、已撤单、已成交及不同产品/窗口订单不能被触发。

当前原型对符合条件的买单按提交时间顺序尝试整笔处理；不够整笔库存或资金的订单不伪造成交。正式排队优先级、是否支持买单部分成交、未能成交订单的重试规则待确认。

## 卖方自己的未成交挂单

卖方拥有单独的未成交列表，展示原挂单面值、剩余未成交面值、价格、金额、有效期和状态，可改价或撤单；已全部成交、撤销和超时订单进入历史记录。若一笔卖单已有部分数量被有效成交消耗，仅剩余部分继续占用库存和允许修改/撤销。撤销不能撤回已经成交的部分。

产品团队接受买单时，可优先消耗同产品同窗口、报价不高于成交价的Group已发布卖单库存，再使用未被其他订单占用的库存；实际消耗量写入卖单轨迹。买方订单当前按整笔接受，不默认开通买单部分成交。

## 资金和状态

当日满足条件的原型交易显示已成交，保留买方原挂单价和实际成交价/金额，生成一次持仓与可追溯成交回执。未来购买可先达成交易，显示已达成、待结算；由于收定金或全额扣款仍未确认，不擅自提前扣款或生成已结算持仓。资金和代币真实原子交割仍需服务端实现。

沿用现有价格基数和费用展示，不在此轮擅自采用有冲突的MVP六公式。卖方本金、买方应付及费用在成交记录中分别保存，正式收费分配待业务确认。

## 保持的规则与技术边界

价格信息每5分钟刷新，刷新本身不等于重新定价或自动成交；报价源时间不伪造为页面刷新时间。挂单超时仍参数化，暂用120分钟演示，最终时长及改价是否续期待确认。超时及撤销释放尚未成交部分占用，已接受交易不按未成交挂单撤销。

当前为静态原型。真实权限、跨用户并发锁、资金及代币账务事务、行情接入、浏览器关闭期间的后台定时撤单，以及未来购买结算，仍需服务端接入；不能将本地记录当作真实资金或链上回执。
